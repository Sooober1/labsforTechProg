# Лабораторная работа 2 — уязвимое веб-приложение

Учебное веб-приложение «Гостевая книга» на Python (Flask) с двумя уязвимостями
из OWASP Top 10, скрипт их эксплуатации и патч.

## Что внутри

| Файл | Что это |
|------|---------|
| `app.py` | Веб-приложение с 2 уязвимостями |
| `exploit.py` | Скрипт, который атакует приложение |
| `patch.diff` | Исправление обеих уязвимостей (формат diff) |
| `app_fixed.py` | Готовая исправленная версия (для сравнения) |

## Уязвимости

1. **SQL-инъекция** (OWASP A03: Injection) — в форме входа логин и пароль
   склеиваются прямо в SQL-запрос. Можно войти как `admin`, не зная пароля.
2. **XSS** (OWASP A03, Cross-Site Scripting) — текст сообщений выводится на
   страницу без экранирования. Можно внедрить `<script>`, который выполнится
   у всех посетителей.

## Как запустить

Нужен Python 3 и Flask:

```bash
pip install flask
```

**Шаг 1.** Запускаем приложение (первый терминал):

```bash
python app.py
```

Открыть в браузере http://127.0.0.1:5000

**Шаг 2.** Запускаем атаку (второй терминал):

```bash
python exploit.py
```

Увидим, что обе атаки проходят успешно.

## Часть 1 — приложение

Код в `app.py`. Места с уязвимостями помечены комментариями
`УЯЗВИМОСТЬ 1` и `УЯЗВИМОСТЬ 2`.

### Как работает SQL-инъекция

Приложение строит запрос так:

```
SELECT * FROM users WHERE username='admin' AND password='<пароль>'
```

Если в поле пароля ввести `' OR '1'='1`, запрос станет:

```
SELECT * FROM users WHERE username='admin' AND password='' OR '1'='1'
```

Условие `'1'='1'` всегда истинно → вход выполняется без настоящего пароля.

### Как работает XSS

Если отправить в гостевую книгу сообщение `<script>alert('Взлом!')</script>`,
оно сохранится и вставится в HTML как есть. У каждого, кто откроет страницу,
браузер выполнит этот скрипт.

## Часть 2 — эксплуатация

Скрипт `exploit.py` по очереди:
1. отправляет на `/login` пароль-инъекцию и проверяет, что вошёл как admin;
2. отправляет сообщение со `<script>` и проверяет, что он попал на страницу.

## Часть 3 — патч

Исправления в `patch.diff`. Применить:

```bash
patch app.py < patch.diff
```

Что меняется:

- **SQL-инъекция** → используем параметризованный запрос
  (`WHERE username=? AND password=?`). Данные передаются отдельно от SQL,
  и их нельзя подмешать в запрос.
- **XSS** → оборачиваем текст в `escape()` перед выводом. `<script>`
  превращается в безопасный текст и не выполняется.

После патча запустить `exploit.py` снова — обе атаки больше не работают.
